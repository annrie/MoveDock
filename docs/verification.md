## 大量ログで「実行中」のままになる問題（2026-09-23）

- 実機の WebKit プロセスをサンプリングし、ログ自動スクロールの `scrollHeight` 読み取りに伴うレイアウト計算が描画を占有していることを確認。転送の子プロセスは終了済みでも、画面に完了が反映されていなかった。
- ログの反映を 100ms ごとにまとめ、最新 2000 行だけ保持。行ごとの DOM を、折り返しのない読み取り専用テキスト欄に変更し、スクロール更新を描画フレームにまとめる。
- 実行状態をログ本文と別に表示。シミュレーションと同期を区別し、終了コードを表示する。ログと状態をコピーするボタンを追加し、Clipboard API のない WebView のフォールバックと失敗表示を用意。
- Vitest 15 件と TypeScript / Vite ビルドが成功。10000 行のバースト、2000 行の上限、終了時の即時反映、コピー成功・失敗・フォールバック、独立した完了表示を含む。
- ブラウザで長いパスを含む 10000 行を約 5.3 秒で表示し、最新 2000 行と「シミュレーション完了・終了コード 0」を確認。ログコピーの成功表示と横方向のページはみ出しがないことを確認。
- Universal アプリを再生成して指定フォルダへ配置。`lipo` で x86_64 / arm64、`codesign --verify --deep --strict` と配置後の実行ファイル一致を確認。
- 更新後の実アプリでテーマ・プラグイン・WordPress 本体の Pull シミュレーションが 9.4 秒で正常終了。2000 行表示中でも UI が応答し、画面の「シミュレーション完了・終了コード 0」まで確認。実サイトの同期・削除は実行していない。
- 実アプリの「ログをコピー」で、終了状態 1 行と最新ログ 2000 行がクリップボードへ入ることを確認。コピー内容に CLI の正常終了表示も含まれる。
- 起動後の最初の環境読み込みは 90 秒でタイムアウトし、再読み込みで成功した。Ruby 起動時の遅延は今回のログ描画修正とは別の既存課題として残る。
